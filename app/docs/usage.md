# Usage and recovery

## Everyday use

Start with app/start.cmd and open http://127.0.0.1:8765. Board shows all tasks by default. Search and owner/assigner filters work in Board and Calendar. Day/week/month filters include scheduled tasks overlapping the selected range; unscheduled tasks remain visible. Use the Archived checkbox to inspect and restore archived tasks. Legacy records are available in a separate read-only tab.

Drag a card into a column to change status, or click/press Enter on a card and choose Status. Drag above another card to reorder; dropping into empty column space puts it at the end. Board order in task details is the keyboard alternative (lower numbers appear first). Calendar dragging changes planned dates. Exact start/end dates are also editable in task details, providing a keyboard alternative. Hard deadline is independent. Move to Backlog to remove scheduling. A Done move reports your completion, not Alex approval.

Open task details to edit title, description, assignment context, source links, dependencies and notes. Save task edits before adding a note. Notes are appended, not overwritten. Sources must already exist under knowledge-base/sources. For a new Alex message, first archive it through /add; alternatively supply an explicit user-reported assignment in the context field. Do not paste credentials into tasks or notes.

If data changes while a task editor is open, the draft is kept and saving against the old version is rejected. Copy any draft text you want to keep, click Load latest task, compare and reapply it. Nothing is silently merged. A connection error retains the form; retrying the same save reuses its operation ID.

## Task commands

All task mutations must use the helper. Start by reading the latest state/token:

```text
python app/tasks.py list
```

Prepare a JSON request in a temporary file or stdin (example only; replace expected with the actual returned token and use a fresh UUID):

```json
{
  "action": "update",
  "id": "T-001",
  "expected": "TOKEN_FROM_LIST",
  "operation_id": "UNIQUE-UUID-HERE",
  "changes": {"status": "In progress"}
}
```

Apply with `python app/tasks.py apply --file <request-file>`. For create, omit id and provide title plus desired fields. For note, use action note, id and text. For archive/restore set archived true/false. Keep the same operation_id when retrying an uncertain save; use a new one for a different intent. A conflict requires a fresh read and a deliberate retry against the new token. Never silently retry stale field values.

The helper works with the server stopped. Next launch reads the latest state. These commands need access to this repository on this computer; they do not run from hosted/cloud conversations without that filesystem.

## Recovery

- **Port in use:** stop your earlier server, or run `python app/server.py --port 8766 --open`. Do not terminate an unrelated process.
- **Interrupted save:** run `python app/tasks.py recover`. Canonical data determines whether the change committed. Retry the same operation ID if uncertain.
- **Manual Markdown edit detected:** preserve the edited file outside the managed projection. Compare its contents with a projection generated from the canonical state. Restore only that projection to the expected generated bytes, then use the helper to apply the intended changes as new events. Do not change projection hashes merely to bypass detection. An agent can use `Store.load()` and `Store.projections(state)` to inspect expected content without writing. User approval is already required for the intended task changes, not for blindly discarding edits.
- **Invalid JSON or missing sources:** stop editing and inspect the error. Restore a known good tracked/copy version or repair the data with source evidence; do not initialize an empty store over the damaged one. UI drafts are not a durable backup; copy them before closing/reloading the page.
- **Rollback the migration:** first preserve tasks.json, task-events.md and any subsequent events. The exact original page is archived in docs/tasks-before-migration.md. Restoring that page alone disables projection consistency; restore a matching pre-app repository state together and stop the service. Do not discard task updates made since migration.
